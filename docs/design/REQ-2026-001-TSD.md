## 一、目标与非目标

### 目标

1. 实现工作台首页的5个功能模块（顶部导航、左侧会话栏、Hero区、输入区、智能体快捷区）
2. 与HiAgent平台对接智能体列表API
3. 与对话服务对接消息发送和历史会话列表
4. 建立前端项目基础架构（路由、状态管理、API层、组件库）

### 非目标

1. 不实现各智能体独立页面
2. 不实现Skills面板详情（仅唤起入口）
3. 不实现全部智能体弹窗详情（仅唤起入口）
4. 不实现配置管理页和资产库管理页
5. 不实现AI对话的后端能力（对接现有UA智能助手Agent）

## 二、现状

### 前端

- 无现有代码，全新项目
- 技术选型：Vue 3 + Vite + TypeScript + Pinia + Vue Router
- UI组件库：Element Plus（Lark风格定制）
- HTTP客户端：Axios

### 后端

- 无现有代码，全新项目
- 技术选型：Java 17 + Spring Boot 3 + Spring Security + MyBatis-Plus
- 数据库：MySQL 8.0
- 缓存：Redis
- 外部依赖：HiAgent平台API、Lark OAuth API

### 可复用组件

- 无（全新项目）

## 三、约束

1. 必须在Lark环境内运行，支持Lark JS-SDK
2. 响应式布局，适配桌面端和移动端
3. 所有API必须经过后端BFF层，不直接调用HiAgent
4. 用户鉴权使用Lark OAuth，Token由后端管理
5. 前端不存储敏感数据，仅存会话ID和用户偏好

## 四、方案概览

采用前后端分离架构：

- **前端**：Vue 3 SPA，部署在Lark小程序/H5容器
- **后端BFF**：Spring Boot服务，负责鉴权、API聚合、缓存
- **外部服务**：HiAgent（智能体列表、对话）、Lark（用户信息）

核心思路：
1. 前端通过BFF获取智能体列表、历史会话、用户信息
2. 对话消息通过BFF转发到HiAgent UA智能助手Agent
3. 文件上传通过BFF中转到文件存储服务
4. 白名单配置由BFF统一管理，前端只接收可见性标志

### 核心调用流

```
用户进入首页
  ↓
前端检查Lark OAuth Token
  ↓ 无Token
跳转Lark授权 → 回调带code → BFF换Token → 存Cookie
  ↓ 有Token
BFF GET /api/workbench/init（聚合接口）
  ├─ 用户信息（Lark API）
  ├─ 智能体列表（HiAgent API + 白名单过滤）
  ├─ 历史会话列表（对话服务）
  └─ 白名单权限（数据库）
  ↓
前端渲染首页各模块
  ↓
用户发送消息
  ↓
BFF POST /api/chat/send → 转发HiAgent → 流式返回
  ↓
前端打字机效果展示
```

## 六、接口契约

### 6.1 初始化聚合接口

**GET /api/workbench/init**

**响应 200**：
```json
{
  "user": {
    "id": "u_123",
    "name": "张三",
    "avatar": "https://...",
    "email": "zhangsan@ua.com"
  },
  "permissions": {
    "can_config_agent": false,
    "can_manage_asset": false
  },
  "agents": [
    {
      "id": "agent_001",
      "name": "服装上身",
      "icon": "https://...",
      "description": "批量生成上身效果图",
      "show_on_home": true,
      "sort_order": 1
    }
  ],
  "recent_chats": [
    {
      "session_id": "sess_001",
      "title": "帮我翻译一下这个合同",
      "last_message_time": "2026-09-14T10:30:00Z",
      "unread_count": 0
    }
  ]
}
```

### 6.2 发送消息

**POST /api/chat/send**

**请求体**：
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| session_id | string | 否 | 新会话时不传 |
| content | string | 是 | 消息内容 |
| files | array | 否 | 附件列表 [{file_id, file_name, file_type}] |

**响应 200（SSE流式）**：
```
data: {"type":"session_start","session_id":"sess_002"}
data: {"type":"text_delta","content":"你好"}
data: {"type":"text_delta","content":"，我是"}
data: {"type":"done"}
```

**错误响应**：
- 400：消息内容为空
- 401：未登录
- 429：发送频率超限（每分钟≤20条）
- 502：HiAgent服务不可用

### 6.3 历史会话列表

**GET /api/chat/sessions?page=1&size=20**

**响应 200**：
```json
{
  "total": 45,
  "page": 1,
  "size": 20,
  "list": [
    {
      "session_id": "sess_001",
      "title": "帮我翻译一下这个合同",
      "last_message_time": "2026-09-14T10:30:00Z",
      "last_message_preview": "好的，这是翻译结果..."
    }
  ]
}
```

### 6.4 文件上传

**POST /api/upload**

**请求**：multipart/form-data，字段名 `file`

**限制**：图片10M、视频50M、音频100M、文档50M

**响应 200**：
```json
{
  "file_id": "file_001",
  "file_name": "合同.pdf",
  "file_type": "application/pdf",
  "file_size": 1024000,
  "preview_url": "https://..."
}
```

**错误响应**：
- 400：文件大小超限 / 不支持的格式

### 6.5 优化提示词

**POST /api/chat/optimize-prompt**

**请求体**：
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| content | string | 是 | 原始提示词 |

**响应 200**：
```json
{
  "optimized_content": "优化后的提示词..."
}
```

## 七、数据模型与迁移

### 7.1 数据库表

**user_whitelist（用户白名单）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 主键 |
| user_id | VARCHAR(64) | Lark用户ID |
| permission_type | VARCHAR(32) | agent_config / asset_manage |
| created_at | DATETIME | 创建时间 |
| created_by | VARCHAR(64) | 创建人 |

**chat_session（会话表）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 主键 |
| session_id | VARCHAR(64) UK | 会话ID |
| user_id | VARCHAR(64) | 用户ID |
| title | VARCHAR(100) | 会话标题 |
| last_message_time | DATETIME | 最后消息时间 |
| created_at | DATETIME | 创建时间 |
| expired_at | DATETIME | 过期时间（30天） |

**索引**：
- `idx_user_time` (user_id, last_message_time DESC)
- `idx_expired` (expired_at)

### 7.2 数据迁移

- 全新项目，无历史数据迁移
- 建表脚本使用Flyway管理
- 白名单表初始为空，由管理员通过后台配置

### 7.3 数据清理

- 会话数据保留30天，过期后定时任务清理
- 清理任务每天凌晨2点执行
- 清理前记录日志，不物理删除，改为逻辑删除（is_deleted=1），保留7天后物理删除

## 八、一致性、并发与幂等

### 并发控制

- 发送消息：用户级别的分布式锁（Redis），防止重复提交
- 历史会话列表：读多写少，无需特殊并发控制
- 白名单配置：管理员操作，加乐观锁

### 幂等性

- 发送消息：前端生成client_message_id，后端去重
- 文件上传：文件MD5+用户ID去重，相同文件直接返回已有file_id

### 缓存

- 智能体列表：Redis缓存5分钟，更新时主动失效
- 用户信息：Redis缓存30分钟
- 白名单：Redis缓存10分钟

## 九、安全与隐私

### 鉴权
- 所有API需要Lark OAuth Token
- Token由后端管理，前端只存Cookie（HttpOnly + Secure + SameSite）
- Token过期自动刷新

### 权限
- 白名单接口校验permission_type
- 会话数据按user_id隔离，用户只能访问自己的会话

### 数据安全
- 对话内容传输加密（HTTPS）
- 文件存储使用私有桶，预签名URL访问（有效期1小时）
- 日志中不记录对话内容，只记录session_id和操作类型
- PII数据（用户姓名、邮箱）仅展示，不导出

### 输入校验
- 消息内容长度限制：≤2000字
- 文件名长度限制：≤100字符
- 文件类型白名单校验

## 十二、发布、兼容与回滚

### 发布顺序
1. 后端BFF服务部署（兼容旧前端，无前端时返回404）
2. 前端静态资源部署
3. 灰度配置开启

### 灰度策略
- 按用户灰度：先内部测试团队（10人）→ 部门级（100人）→ 全量
- 灰度观察期：每级3天
- 晋级条件：错误率<1%，无P0/P1缺陷

### 兼容性
- 前端新版本兼容旧版后端（后端API版本化/v1）
- 后端新版本兼容旧版前端（新增字段不影响旧前端）
- 数据库变更：只加字段不删字段，双写过渡

### 回滚方案
- **触发条件**：错误率>10%、核心功能不可用、P0缺陷
- **回滚步骤**：
  1. 前端回滚到上一版本（CDN切换，<1分钟）
  2. 后端回滚到上一版本（K8s滚动更新，<5分钟）
  3. 数据库：无DDL变更，无需回滚
- **RTO**：<10分钟
- **数据恢复**：无数据变更，无需恢复
